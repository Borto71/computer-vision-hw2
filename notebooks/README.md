# Notebook Workspace

This directory accommodates exploratory and analytical notebooks that generate insight from training runs. Use it as the central location for evaluating metrics, investigating model behaviour, and communicating experimental findings.

## Intended Contents
- Performance dashboards that visualise metrics emitted by `main.py` or companion scripts.
- Exploratory analyses that examine failure cases, confusion matrices, calibration, or attribution results.
- Lightweight investigations that inform future experiments, such as hyperparameter searches or augmentation studies.

Training logic itself should reside in scripts or modules; notebooks focus on analysis and reporting.

## Alignment with `main.py`
- Treat `main.py` as the canonical entry point for model training and evaluation. Its outputs (logs, checkpoints, and serialised metrics) feed the notebooks located here.
- When new metrics or artefacts are produced, document the loading process within the relevant notebook cells.
- Maintain a “Run Checklist” cell at the top of each notebook describing prerequisite commands (for example, `python main.py --config run.yaml`) before executing the analysis.

## Collaboration with `utils/`
- Reuse helpers from `utils/` for plotting, metric formatting, file handling, or configuration.
- Promote widely useful analysis snippets into appropriately named functions within `utils/`, then import them in notebooks.
- Avoid duplicating logic already provided by shared utilities to keep notebooks concise and maintainable.

## Recommended Workflow
1. Collect the latest artefacts generated by `main.py` into the expected `data/processed/` or `artifacts/` subdirectories.
2. Duplicate the base template (for example, `notebook.ipynb`) and rename it to reflect the experiment: `analysis_loss_curve.ipynb`.
3. Begin with a summary section that records objectives, run identifiers, and key metrics.
4. Build the analysis narrative with clear visualisations and commentary on findings.
5. Conclude with actionable recommendations or hypotheses for the next iteration.

## Maintenance Guidelines
- Ensure “Restart & Run All” completes without manual intervention by parameterising inputs where required.
- Remove large intermediate outputs (for example, extensive tables or embedded binaries) prior to committing changes.
- Reference issues, pull requests, or experiment trackers that prompted the analysis to preserve traceability.

The notebooks in this directory should provide reproducible, insight-driven documentation of the project’s experimentation efforts.
